# P6：工单检索调用带引用的问答

设置 `RAG_BASE_URL` 后，分流图的知识库检索改为调用 [citation-rag-agent](https://github.com/lyu24944-cmyk/citation-rag-agent) 的 `POST /ask`。分类、人工审核和结案仍在本仓库。对不上文档时问答服务返回空引用，草稿里也不会出现引用。

未设置 `RAG_BASE_URL` 时，仍用本仓库的关键词知识库。MCP 工具面也仍走关键词实现。

## 怎么跑

先在问答仓库启动 API（第一次会下载句子嵌入模型）：

```powershell
cd ..\citation-rag-agent
.\.venv\Scripts\python.exe -m uvicorn citation_rag.api.main:app --host 127.0.0.1 --port 8001
```

再让工单服务使用它：

```powershell
$env:RAG_BASE_URL="http://127.0.0.1:8001"
uvicorn ticket_triage.api.main:app --port 8000
```

本仓库会在第一次检索时把三篇政策入库。文档编号仍是 `kb-billing-refund`、`kb-tech-reset`、`kb-account-delete`，所以原来的黄金集前缀检查继续适用。交给问答服务的正文在中文政策后附了英文直译，英文工单才能过 0.50 的相似度门槛。英文只能翻译原文，不能补充原文没有的说法：用真实模型起草时，摘录里的每句话都可能被写进回复。

一条命令演示（会自己启动并关掉 8001 上的问答服务）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\demo_p6.ps1
```

## 完成标准

1. 不设置 `RAG_BASE_URL` 时，`pytest` 与 `python evals/run_evals.py` 仍按关键词知识库通过。
2. 设置 `RAG_BASE_URL` 后，同一套黄金集通过：该引用的工单带上 `kb-billing` / `kb-tech` / `kb-account`，闲聊和天气没有引用。
3. 问答服务连不上时，检索记为 `enrich_failed`，重试后仍起草，且草稿没有引用。
4. 分类、人工审核、结案不搬到问答仓库。MCP 的三个工具仍是关键词实现。
